# Dalamud Plugin Repository Merger

Merges many Dalamud custom plugin repositories into a single `repository.json`, so users only have to add one URL to the game. The merge runs automatically every 5 minutes on GitHub Actions, and anyone can submit a new repository by opening an issue.

## Using the merged repository

Add this URL as a custom plugin repository in Dalamud:

```
https://raw.githubusercontent.com/WilliamW1979/FFXIV/main/repository.json
```
[https://raw.githubusercontent.com/WilliamW1979/FFXIV/main/repository.json](https://raw.githubusercontent.com/WilliamW1979/FFXIV/main/repository.json)

## Submitting a repository

1. Open a new issue and choose **Submit a plugin repository**.
2. Paste the direct URL to your repo JSON file.
3. Wait a minute or two. A bot replies on the issue and closes it.

If the repository passes every check it is added immediately and shows up in the next merged `repository.json`. If it fails, the reply explains why. Fix the problem and open a new submission.

If on the rare chance that a working plugin is not being read here, please submit an issue so that I can look into it. Generally this script only reads the original JSON and creates a new MEGA JSON so it shouldn't have any problems.

### Submission requirements

- The URL is `https://`, on a public domain name, 300 characters or fewer, with no credentials, custom port, IP address or internal host.
- The URL is not on the blocklist, not already in the list, and not currently quarantined.
- The repository can be read and contains at least one plugin.
- Every plugin has an `InternalName` and a `Name`. `InternalName` may only contain letters, digits, dots, dashes and underscores (64 characters max).

## How the merge works

Each run does the following:

1. Reads `RepoList.txt` and drops anything matching `Blocklist.txt`.
2. Fetches the repositories, up to 4 at a time, with retries. A repository whose server reports it unchanged since the last run (via `ETag` or `Last-Modified`) is not downloaded again, and its cached plugins are used instead. Every repository is still fully re-fetched at least every 6 hours. Plugins missing `InternalName` or `Name` are skipped with a warning.
3. Normalizes each plugin: a missing `Author` becomes `Unknown`, and `RepoUrl` and `SourceRepo` are filled in.
4. Deduplicates by `InternalName`. The winner is the entry with a download link, then the higher `AssemblyVersion`, then the one with more fields. The other sources are listed in `AlternateSources`. If the copies come from different authors, a warning is logged, since that usually means two different plugins share one `InternalName`.
5. Writes `repository.json` and the report files, then commits and pushes if anything changed.

## Quarantine

If a repo no longer exists or can't be read after 3 days of attempting, it gets moved to the Quarantine file. This location will be checked by the script every 6 hours instead of every 5 minutes and will no longer flag an error. This is for Repositories that are shut down and no longer exist, which helps clean up the main `repository.json` file. Just in case there was a major power outage from a hurricane or some other event, the quarantine file still gets checked every 6 hours in case a repository comes back online. So Quarantine files are never completely gone, just checked less often. As soon as the repository comes back online, it is moved back to the main repository list and the 3 day inactive is reset.

### Notes

1. I originally wrote this in JavaScript but re-created the same script in C# so that it could run more efficiently and effectively. I have it set it to email me if there are any problems with how it runs so I will be closely monitoring it from this day forth.
2. All of the TXT files that are generated by the script are public. Even though there is an option to save everything to a private repository, I felt that keeping everything public so everyone can see what is happening was the best way to handle this project. I didn't see any private data that needed to be hidden as the JSON files are all public that are being read and combined.
3. The stats.txt will update every 2 minutes and display the repository count, the mod count, any errors (errors flagged here will move to Quarantine in 72 hours), and some other interesting information. All TXT files were generated by the script.
4. An error flag doesn't mean the repository is broken, it just means that one of the repositories used in created the MEGA repository list is having issues and won't be in the MEGA repository list until it is fixed. These errors won't affect usage or gameplay, just some mods might not be available until the owner fixes them. If they won't work here, they won't work in Dalamud directly.
